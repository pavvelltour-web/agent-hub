# Agent Hub v0.1 — отчёт: что сделано, как работает, как запускать

> 22 октября 2026. Всё локально, на GitHub ничего не выложено. 77 автотестов, строгий `tsc`, 14 проверок безопасности — зелёные.
> Статусы: **проверено** (запускал и видел), **по документации** (источник — официальные доки, в живой сессии агента не гонял), **не проверено**.

## 1. Главный вывод про токены

Расход токенов на каждый ход определяется не «всеми инструментами», а тем, **что агент загружает в любой проект автоматически**. На вашем ПК (проверено):

| Что | Сколько | Кто платит |
|---|---|---|
| Плагины Claude (≈100 шт.) | **≈ 19,6 тыс. токенов на каждый ход** | Claude, в каждом проекте |
| из них «вероятно не нужные» (Firebase, AWS, Atlassian, Figma, Airflow…) | ≈ 18 тыс. | Claude |
| Личные скиллы Claude (`~/.claude/skills`) | 3 штуки (копейки на фоне плагинов) | Claude |
| Скиллы Codex (`~/.agents/skills` 70 + `~/.codex/skills` 54) | 124 шт.; список Codex сам режет до ≈ 2 тыс. токенов (2 % окна, по документации) | Codex |

Раньше панель писала «124 скилла видно агентам» — это смешивало Claude и Codex и было неверно. Теперь у каждого скилла есть **область видимости** (кто его грузит и где), и цифры считаются честно по агентам.

**Профиль проекта на реальных данных:** в тестовом проекте «Оставить только нужное» снизило Claude с 19,6 тыс. до 1,9 тыс. токенов на ход (−90 %). Применено через план → подтверждение → резервная копия.

## 2. Как устроена «инструменты только под проект»

Три уровня, от самого надёжного:

1. **Новое — только в библиотеку hub, не в папки агентов.** Всё, что вы находите и ставите через панель, попадает в `~/.agent-hub/skills` (скиллы) и `~/.agent-hub/registry` (MCP). Ни Claude, ни Codex эти папки сами не читают, поэтому инструмент стоит **0 токенов**, пока вы не подключили его к проекту. Подключение = ссылка (junction) в `.claude/skills` и `.agents/skills` **этого** проекта. Это единственный способ, который не зависит от того, как агент трактует настройки.
2. **Уже установленное глобально — профиль проекта** (запись только в этот проект, только после плана):
   - Claude, скиллы: `skillOverrides` в `.claude/settings.local.json` — `off` (скрыть) или `name-only` (в контексте только имя, скилл остаётся доступным). *По документации.*
   - Claude, плагины: `enabledPlugins: {id: false}` там же. *По документации.* (`skillOverrides` на скиллы плагинов не действует — их выключают только так.)
   - Codex: блок `# >>> agent-hub:plugin-profile` в `.codex/config.toml` с `[[skills.config]] enabled=false` и `[plugins."id"] enabled=false`. **Не проверено**, что Codex учитывает эти ключи на уровне проекта (в доках они описаны для глобального `~/.codex/config.toml`).
   - Файл Claude личный (`settings.local.json`, не для git): это ваш выбор по вашим установкам, не правило команды.
3. **MCP.** Серверы проекта живут в `.mcp.json` и `.codex/config.toml` — только в проекте. Серверы пользовательского уровня Claude (`~/.claude.json`) панель **не читает и не меняет** (там могут быть токены, формат переключателя в доках не показан): переключайте их внутри Claude командой `/mcp` — выбор запоминается по проекту. Цена MCP за ход показана как «неизвестна»: Claude подгружает их описания по запросу (tool search), выдумывать число не стал.

Чего hub **не делает**: не удаляет и не редактирует ваши глобальные скиллы и плагины, не пишет в `~/.claude` и `~/.codex`.

## 3. Как это выглядит в панели

Проект → вкладка **«Инструменты»** (одна точка входа вместо прежней «Библиотеки»):

1. **Сводка:** два счётчика (Claude / Codex) «токенов на каждый ход»; при ваших переключениях показывает «было → станет (−N %)» сразу, до записи.
2. **Скиллы / Плагины / MCP:** строка = инструмент, цена в токенах, у кого загружается, состояние `Активен · Только имя · Выкл`. Изменённые строки подсвечены; внизу липкая панель «Изменений: N → План и применить».
3. **«Оставить только нужное»:** предлагает набор по типу проекта и `brief.md` (то, что уже подключено к проекту + топ-8 от скаута остаётся; лишние глобальные скиллы → «только имя», плагины из списка «вероятно не нужных» → «выкл»). Ничего не пишет, пока вы не нажмёте «План и применить».
4. **Найти:** три источника — ваша библиотека, aitmpl.com (≈ 890 скиллов, ≈ 110 MCP), GitHub (через `gh`).
   - aitmpl: «Посмотреть и добавить» показывает **весь текст**, список файлов, лицензию, **проверку самого каталога** (skillspector: LOW/MEDIUM/HIGH) и есть ли скрипты. HIGH/CRITICAL, бинарные файлы, небезопасные пути, дубли имён — **блокируются**. Затем «Добавить в библиотеку» → план → подтверждение (на сервере проверяется digest: apply принимает только то, что вы видели).
   - Дальше «Подключить к проекту» (обычный план `init`). Убрать — «Убрать из проекта» (удаляет только ссылку, не сам скилл; откат одной кнопкой).
   - GitHub: показывается команда `git clone`, сам hub ничего не качает.
5. Новый проект: баннер «подключить к hub» с выбором типа; кнопка «Откатить последнее».

Командная строка (то же самое): `hub tools`, `hub profile --off a,b --name-only c --plugin-off id`, `hub get aitmpl/skills/<cat>/<name>`, `hub init --add/--remove`, `hub scout --source aitmpl|github`.

## 4. Как запустить

```bash
cd C:\Users\<user>\Desktop\agent-hub
node bin/hub.js ui --demo      # демо: сценарные «агенты», лимиты не тратятся; печатает ссылку с токеном
node bin/hub.js ui             # настоящий режим (Claude CLI нужно один раз залогинить: claude → /login)
node bin/hub.js tools .        # что грузится в этом проекте, по убыванию стоимости
npm test && npm run typecheck && npm run security
```

Первый заход: «Сегодня» → «Обновить историю» (читает `~/.claude`, `~/.codex` только на чтение) → «Проекты» → проект → «Инструменты» → «Оставить только нужное» → «План и применить».
Свой пайплайн дизайна: Настройки → «Свои папки со скиллами» → путь `C:\Users\<user>\Desktop\design-pipeline-2026-10-18-v15` (скиллы в `plugin/skills/*` находятся; пока не подключены к проекту, стоят 0).

## 6. На что обратить внимание

1. **Проверьте `skillOverrides` вживую один раз:** откройте Claude в проекте после «Применить» → `/skills` (там должны быть выключенные) и `/skill-doctor` (цена контекста). Если Claude не учтёт — вся механика уровня 2 для Claude превращается в «советы»; уровень 1 (библиотека hub) работает всегда.
2. **Codex:** профиль на уровне проекта не подтверждён. Проверка: запустить `codex` в проекте и посмотреть список скиллов; иначе остаётся уровень 1 или глобальный `~/.codex/config.toml` вручную.
3. **Не меняйте профиль посреди чата:** смена списка скиллов ломает кэш промпта. Применяйте на старте задачи.
4. **«Только имя» безопаснее «Выкл»:** скилл остаётся вызываемым командой `/имя`, но почти ничего не стоит. Для точности агентов начинайте с «только имя», «Выкл» — для заведомо чужих (Firebase в Telegram-боте).
5. **Плагины — главный расход.** Скиллы Claude почти бесплатны (3 шт.); основная экономия — на плагинах.
6. **Каталожные тексты — данные, не инструкции.** Установка в панели ничего не исполняет, но подключённый скилл со скриптами агент потом может запускать: читайте предпросмотр (чип «есть скрипты»).
7. **MCP-ключи** hub нигде не хранит: в библиотеку попадают только имена переменных окружения, значения задаёте сами.
8. Сторонний каталог aitmpl — лицензии бывают «Complete terms in LICENSE.txt» или пустые: панель показывает «не указана», решение за вами.

## 7. Идеи для доработки (по ценности)

1. **Профиль по этапу жизненного цикла.** На этапе «GrillMe» нужны только grill/brainstorm, на «дизайн» — design-пайплайн, на «код» — TDD/ponytail. Hub переключает профиль при подтверждении этапа: самая сильная экономия без потери точности.
2. **Чистка по фактическому использованию.** История уже в SQLite: посчитать, какие скиллы реально вызывались за 30 дней, и предлагать выключать «ни разу не вызванные» (аналог `/skill-doctor`, но по обоим агентам и по проектам).
3. **«Вынести глобальное в библиотеку hub»:** план «переместить скилл из `~/.claude/skills` / `~/.agents/skills` в `~/.agent-hub/skills`» (с резервной копией и откатом) — глобальный налог станет нулевым, а нужное подключается по проектам.
4. **Замер качества после триммирования:** `eval/golden` с 5–10 эталонными задачами, A/B «до/после профиля» (успех, токены) — чтобы экономия не ломала точность.
5. **MCP уровня пользователя:** план правки `~/.claude.json` (после выяснения формата `disabledMcpServers`) + показ реальных списков, включая коннекторы claude.ai.
6. **Хуки:** перевод событий уровня инструментов (PreToolUse и др.) — нужен собственный shim-слой; сейчас они только перечисляются как «пропущено».
7. **Счётчик «токенов на ход» в шапке чата** и предупреждение «профиль изменён, начните новый чат».
8. **Подписи и SBOM для библиотеки**: хэш каждого установленного скилла в `hub.lock`, проверка при `hub install` на другой машине (уже есть для локальных), отчёт по лицензиям.
9. **Командные профили:** отдельный общий файл профиля для git (`hub.profile.json`), а личные отклонения — в local.
10. **Английский интерфейс, macOS/Linux, Docker-сканеры, автотесты UI** (Playwright уже есть для скриншотов).

## 8. Файлы

`src/core/loading.ts` (аудит и профиль), `src/core/install-remote.ts` (предпросмотр и установка из каталога), `src/core/hooks-adopt.ts`, `src/run/hooks-run.ts` (одобрение хуков), `web/js/views/tools.js` (экран), `registry/plugin-profile.json` (список «вероятно не нужных»). ## Агентские правила для каждого типа работы (проверено и усилено)

Раньше любой проект получал один и тот же AGENTS.md из четырёх строк. Теперь `rules/base.md` + `rules/<тип>.md`, собираются при подключении проекта:

- **Общее для всех:** с чего начать (brief, задача, граф), жёсткие запреты (секреты, push, платные вызовы, зависимости, чужой текст = данные, опасные действия только с подтверждением, язык ответа, «неизвестно» вместо выдумки), **как работать по видам задач** (план / код / отладка / ревью / рутина), какие модели и глубина, экономия токенов, какие скиллы когда, что делать при остановке, критерии готовности. Файл короткий (≈ 60 строк), потому что агент читает его каждый ход.
- **Сайт / веб-сервис:** контракты API сначала, проверка прав на сервере, ключи не в браузере, миграции обратимы, проверка интерфейса в браузере (десктоп и 375 px, светлая и тёмная), доступность, тесты на основные сценарии.
- **Мобильное приложение:** сначала определить стек, касания ≥ 44 pt, безопасные зоны, плохая сеть, секреты не в приложении, разрешения по месту, правила магазинов, проверка релизной сборки, скриншоты экранов.
- **Бот, автоматизация, агенты:** по умолчанию безопасно (dry-run, человек подтверждает), повторяемость (идемпотентность), таймауты и ограниченные повторы, лимиты стоимости, секреты из окружения, подпись вебхуков, промпты в файлах, эталонные задачи, журнал каждого шага.
- **Дизайн-исследование:** результаты в `design/` и `research/`, никаких выдуманных данных и цитат, минимум два варианта, цвета и шрифты в токенах, контраст ≥ 4,5:1, честно написано, что проверено и что нет.
Тест проверяет: у каждого типа свой раздел, чужие разделы не просачиваются, плейсхолдеров нет, файл остаётся коротким.

## Что нашёл при проверке библиотеки и исправил

1. **`ponytail` в наборах «обязательных» не установлен на этом ПК**, а `product-ui-workbench` и `design-quality-loop` лежат вне стандартных папок. Раньше init молча пропускал их. Теперь план прямо пишет по-русски: что не найдено, куда добавить папку (Настройки → «Свои папки со скиллами»), какая команда установки у не установленного скилла.
2. **Подсказки «плагин не нужен» были одинаковы для любого проекта** (например, предлагали выключить Figma для дизайн-исследования). Теперь список зависит от типа проекта (`keepFor` в `registry/plugin-profile.json`).

## 2. Выбор модели: не правило, а ближайшая точка к идеалу

Раньше «Claude проверяет GPT» было фиксированным правилом. Теперь это **оптимизатор** (`src/econ/router.ts`):

- Каждая модель — точка: **качество** (0–1) и **цена** (доля от самой дорогой модели на типичной задаче). Идеал — левый верхний угол: лучшее качество за ноль. Выбирается модель, ближайшая к идеалу. Карта показана на странице «Модели».
- **Качество** = (5 × оценка автора + сумма результатов ваших запусков) / (5 + число запусков). Оценка автора — стартовая догадка, **не измерение**; меньше 3 запусков не учитываются; после накопления данных ваши результаты вытесняют догадку.
- **Результат запуска:** ваша оценка «Получилось? Да / Частично / Нет» после задачи в чате; без оценки «готово» считается слабым «да» (0,7), «ошибка» — нулём; остановка по лимиту качество не меняет.
- Вес цены зависит от работы: для планов качество важнее, для рутины цена. Переключатель «Что для вас важнее» (только качество … только цена) меняет баланс.
- Ревью другим вендором — **бонус к качеству**, а не жёсткое правило: оптимизатор может выбрать и своего, если он явно выгоднее.
- Нагрузка: если у агента лимит почти выжат, а у другого запас, выбор смещается к тому, где запас.
- **Обучение:** по желанию (галочка) в 1 из 10 простых задач hub пробует менее изученную модель, чтобы узнавать, где можно сэкономить. По умолчанию выключено.
- Жёсткие рамки остаются: безопасность → Opus, шаг не прошёл 2–3 раза → лестница вверх, агент без лимита исключается.
- **Цена GPT не известна**, поэтому считается равной Sonnet и помечена как допущение.

## 3. Сбор данных пользователей с согласия

Сделана клиентская часть, **отправки нет**: сервера для приёма у проекта пока нет, и без политики конфиденциальности отправлять данные нельзя.

- **Согласие** в «Настройках → Помочь улучшить прогнозы»: выключено по умолчанию, снимается в любой момент, после снятия сохранение файла сразу блокируется.
- **Что собирается:** на каждую завершённую задачу одна запись: тип задачи, тип проекта, агент, модель, глубина мышления, исход, оценка пользователя, расход токенов (округлён «ступеньками» ×1,8), цена в долларах, минуты, была ли передача/продолжение, попал ли прогноз в диапазон, неделя года.

Если пользователи в РФ, нужен учёт закона о персональных данных (152-ФЗ); это не юридическая консультация. Данные устроены так, чтобы персональными не быть, но решение о форме принимает юрист.
