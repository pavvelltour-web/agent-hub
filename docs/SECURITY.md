# Agent Hub — безопасность и проверка уязвимостей

> Статус: **черновик v0.1**, 2026-10-22. Связано с [ARCHITECTURE.md](ARCHITECTURE.md), раздел 7.

Панель запускает агентов, пишет им конфиги и ставит чужие компоненты. Это даёт ей широкие права, поэтому безопасность — отдельная задача, а не последний шаг.

## 1. Модель угроз (что может пойти не так)

| № | Угроза | Как проявляется | Защита |
|---|---|---|---|
| T1 | Вредоносный компонент каталога | скилл или хук выполняет опасную команду; текст компонента содержит инструкции агенту | фиксация версии и хэша, показ точной команды, поле `risk` в записи, установка только после «OK», текст каталога = данные |
| T2 | Подмена пакета (typosquatting) | установлен пакет с похожим именем | установка только из официального источника, сверка имени и владельца, хэш |
| T3 | Prompt injection через чужие файлы | `AGENTS.md`, README или спецификация из клонированного репозитория меняют поведение агента | правила проекта подтверждаются при первом открытии; панель показывает изменения в `AGENTS.md` перед запуском |
| T4 | Утечка секретов в индекс или лог | ключ из терминала попадает в сообщение истории | вырезание по шаблонам до записи в БД, чёрный список путей (`auth.json`, `.credentials.json`, `secrets/`), секреты MCP только ссылкой на переменную окружения |
| T5 | Атака на локальный сервер | страница в браузере обращается к `127.0.0.1` (CSRF, DNS rebinding) | слушать только `127.0.0.1`, токен сессии, проверка заголовков `Host` и `Origin`, запрет CORS |
| T6 | Выход за пределы проекта | `..` в путях, ссылки и junction ведут в чужие папки; компилятор пишет не туда | каноникализация путей, запись только внутри разрешённых корней, проверка junction и symlink до записи |
| T7 | Внедрение команд в раннере | имя задачи или ветки попадает в командную строку | запуск процессов массивом аргументов без shell, строгая проверка имён веток |
| T8 | Агент делает лишнее | `git push`, удаление, сеть | права агента урезаны по умолчанию, запрет `push`, песочница; `unsupported` вместо молчаливого понижения защиты |
| T9 | Подмена обновления панели | вредоносная версия `agent-hub` | публикация с подтверждением происхождения пакета (provenance), блокировка зависимостей lockfile, двухфакторная защита аккаунта npm |
| T10 | Чужой запуск: harness2 и подобные | инструмент отключает песочницу Codex и открывает сеть | не подключаем без решения; если подключаем, то только в Docker или WSL с ограничением сети |

## 2. Проверки на каждой части

Каждая часть сборки (1–5) проходит ворота безопасности **до слияния**:

| Проверка | Чем | Статус на вашем ПК |
|---|---|---|
| Уязвимости зависимостей | `npm audit`, `osv-scanner` | `npm` есть; `osv-scanner` не установлен |
| Секреты в коде и истории git | `gitleaks` | не установлен |
| Статический анализ кода | `semgrep` | не установлен |
| Образы и конфиги | `trivy` | не установлен |
| Ревью безопасности diff | скиллы `security-review`, `security-best-practices` (есть в AmpliCore, JS/TS), `review-security` | есть |
| Пентест веб-интерфейса и сервера | скиллы `penetration-testing-with-strix`, `fix-security-vulnerabilities-with-strix`, `ci-security-scanning-with-strix` в `~/.agents/skills` | скиллы есть; требования Strix не проверялись |
| Внешний сканер | Aikido (`aikido:scan`) | нужна авторизация; код уходит во внешний сервис, решаете вы |
| После публикации на GitHub | Dependabot, secret scanning, CodeQL | включаются в настройках репозитория |

Установленного сканера нет, но Docker установлен (запущен ли демон, не проверял), поэтому `gitleaks`, `semgrep`, `osv-scanner` и `trivy` запускаем контейнерами без установки на ПК. Команда `hub security` оборачивает набор и пишет отчёт в `.hub/security/`.

## 3. Ворота безопасности (требования к слиянию)

1. Нет секретов в коде и в истории (`gitleaks` чисто).
2. Нет известных уязвимостей высокого уровня в зависимостях или они обоснованно отложены с записью в ADR.
3. Нет находок `semgrep` высокого уровня.
4. Для частей 1 и 3: ревью другим агентом отдельно по списку T1–T10.
5. Тесты на негативные случаи: путь `..`, junction на чужую папку, имя ветки с пробелом и `;`, секрет в логе, запрос к серверу с чужим `Origin`.

## 4. Проверка сторонних компонентов при установке

Перед записью в `hub.lock` компонент получает оценку риска:

- запускает ли код (хук, команда, MCP-сервер), обращается ли к сети, пишет ли вне проекта;
- есть ли в тексте скрытые инструкции агенту («игнорируй правила», обходы подтверждений) — эвристика и список шаблонов;
- возраст источника, число авторов, давность последнего обновления, лицензия;
- результат сканера (`semgrep`/`osv`) для исполняемых файлов.

Высокий риск не блокирует установку, но выносится красной пометкой и требует отдельного подтверждения.

## 5. Что не гарантируем

- Панель не защитит от вредоносного кода, который вы сами подтвердили после просмотра.
- Эвристика скрытых инструкций ловит не всё.
- Условия подписок при запуске CLI сторонним оркестратором не проверены (см. ARCHITECTURE, раздел 12).
