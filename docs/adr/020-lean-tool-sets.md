# ADR-020: a run starts only the skills and MCP servers its work mode needs

Context: every skill listing and every MCP tool list a Claude Code session loads is paid on every turn. The work mode already says what a task is for, so it can also say what the run may load. The risk is on the other side: a flag that hands the agent a server definition is a way to run a command.

Decision (`src/run/lean.ts`, `leanPlan`):
- **Skills are on or off, not filtered.** A mode whose `skills` is empty starts with `--disable-slash-commands`. Any non-empty list keeps skills on; `["*"]` is the explicit "all" (the only wildcard, and it stands alone), names such as `autopilot` say which skill the mode relies on. Shipped: chat and task `["*"]`, autopilot `["autopilot"]`, interview and review `[]`. A run without a mode keeps the old class rule (mechanical, summary).
- **Optional skills (Phase 5.3).** A mode may carry `skillsIfLinked: [names]` (names only, never `*`). Interview carries `["grill-me"]`. For Claude, a listed skill that is linked (SKILL.md in the project's or the user's `.claude/skills`) makes the list effectively non-empty: skills stay on and the prompt starts with `/grill-me`. None linked: skills stay off, the prompt is unchanged, nothing fails, and the run gets a `warn` event ("skill grill-me is not linked: interview runs without it"). Codex gets neither the slash command nor a note (no skill key was verified). The check is a file-existence test of fixed folders, never a read of credentials. **Trust:** only the user's own `~/.claude/skills` and a project link that resolves into the hub library (`<hub home>/skills` or a folder added with `hub config add-skill-root`) count; a plain `.claude/skills/<name>` folder inside the project does not, because a cloned repository can ship one and the hub would then type `/<name>` for it. **Cost:** with `grill-me` linked, Interview loads ALL skills (a slash command needs them on; the CLI has no per-skill switch that was verified), so its first call is as large as a chat's; without it, Interview stays off.
- **MCP.** A mode may carry `mcp: [names]` (even `[]`). A mode that sets it always gets `--strict-mcp-config`; with servers needed it also gets `--mcp-config <file>` holding only those. The caller can narrow the mode's list, never widen it. `mcp: []` means no MCP at all. A mode without `mcp` leaves MCP as the user configured it.
- **Where a definition comes from.** Only the hub library (`mcp/<name>` entries: shipped catalog, then `<hub home>/registry`). On an id collision the **shipped entry wins**, in the panel (`library()`) and in a run alike, so what the panel shows is what a run starts. Never the project's `.mcp.json`: `--mcp-config` is trusted without the approval prompt project-scoped servers get, so a repository could name a hostile command under a known server name.
- **What an entry may contain.** No `$` in `command`, `args` or `url` (the only `${NAME}` in the file is the one the hub generates from a validated env name, so an entry cannot have the CLI expand `${ANTHROPIC_API_KEY}` into a url or an argument); `https://` only; no shell launcher as `command` (cmd, powershell, pwsh, sh, bash, zsh and similar, with or without a path or `.exe`), whatever its arguments; no control characters; headers are not carried; `sourceVerified` must be true unless the entry is in the shipped catalog.
- **Fail closed, all or nothing.** If any needed server is refused, or the file cannot be written safely, **no** MCP server starts in that run (strict, no file) and a `warn` event says which server and why. Never the user's whole set (fail-open), never a half list.
- **File handling.** Created with `wx` and mode `0600` in `<hub home>/tmp`, not the project folder or a shared temp folder; removed when the process ends, or at once if starting the process throws; files named `mcp-<16 hex>.json` older than a day are swept when a `RunManager` is created. **Limit:** `0600` is ignored on Windows, where the file is protected only by the folder's ACL. So on Windows the folder (canonical path, junctions resolved) must be inside the user profile, otherwise the MCP part is refused as above. `--mcp-config` takes several values, so it is the last flag emitted. Review-gate reviewers (`isolatedCwd`) get no lean flags at all.
- **Unknown mode.** A `workMode` whose mode is not found, or whose file is malformed, falls back to the class rule and says so with a `warn` event.
- **Codex.** Nothing is passed: Task 1.2 verified `sandbox_mode` and `model_reasoning_effort` only; no `-c` key for skills or MCP is verified.

Status: flags are in `claude --help` (observed, v2.1.114); argument assembly, file contents, cleanup, sweep and the warns are tested with a fake agent. The effect on a real session's first-call size was **not measured** (CLI not signed in), and the expansion of `${NAME}` inside `--mcp-config` files is documented `.mcp.json` behaviour that was **not run live** here; neither was `--strict-mcp-config` without `--mcp-config` (it should start no server).
Tests: `src/run/lean.test.ts`, `src/run/run.test.ts` (lean), `src/core/core.test.ts` (catalog precedence).
