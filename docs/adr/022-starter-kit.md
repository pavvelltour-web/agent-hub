# ADR-022: the starter kit installs third-party skills into the hub library only, from named repositories, at a pinned commit, after the user was shown every byte

Context: the first-run wizard offers a short list of skills (`registry/starter.json`). Installing them means fetching text from the internet that an agent will later treat as instructions, so what is fetched, from where, what the user sees and where it lands is a security decision. The existing `hub get aitmpl/...` path (`src/core/install-remote.ts`) already shows the whole component first and only accepts what was previewed; this reuses that machinery and tightens it for a source that is a git repository.

Decision (`src/core/starter.ts`, `registry/starter.json`, `src/server/api.ts` `GET /api/starter`, `POST /api/starter/plan|apply|undo`, `web/js/views/welcome.js`, `web/js/views/starter-dialog.js`):
- **The list is data.** `registry/starter.json` is validated on load: safe ids, `owner/repo`, a relative safe path, a mandatory `license` (the word `unknown` means unchecked), unique ids, source type `github` or `manual`. A `github` entry needs a **40-hex `ref`**. An entry without one (missing, a branch name, `latest`, `HEAD`) loads as **`unpinned`**: it is listed with the reason ("не закреплён на коммите…") and is **never fetched**; a human must put a real sha into the file. A garbage `ref` is a load error. A `manual` source (a program installed by its own command, or a skill whose source was not verified) is listed with its reason and never fetched.
- **What is pinned today.** The three `obra/superpowers` skills (`test-driven-development`, `systematic-debugging`, `verification-before-completion`) are pinned to `bb92a77741419a4ab5f06e711a283343f1ada0c3`. Provenance (observed offline, read-only): the `superpowers` entry of the local `claude-plugins-official` marketplace (`marketplace.json`) pins `https://github.com/obra/superpowers.git` at that sha, and `installed_plugins.json` records the same `gitCommitSha` for the installed 7.0.0; the cached 7.0.0 holds `skills/<id>/SKILL.md` at those paths with the byte sizes the preview shows (9578, 9530, 3646). **Not verified:** that GitHub serves exactly those bytes for that sha (no network use). The hub shows the sha, and the user reads the bytes.
- **Where it may be fetched from.** The fetcher is built from the repositories named in the list: https only, no port, no credentials, no redirects, 20 s per request, an outer 60 s budget per skill, size caps enforced **while the body streams** (a body that never ends is cut off, not buffered). Only `api.github.com/repos/<repo>/git/trees/<sha>?recursive=1` and `raw.githubusercontent.com/<repo>/<sha>/...` of a listed repository are allowed. No branch is ever read.
- **What is accepted.** Only the folder `<path>/` of the pinned commit: regular files (git modes 100644/100755). Each of these refuses that skill with the reason: a symlink (120000), a submodule, a truncated tree, a path outside `[\w.-]/` segments or with `..`/`.git`, a name Windows cannot hold (NUL, CON, `:`, trailing dot, two names equal but for case: the review copy's `pathProblem`), a binary file (NUL), **any invisible or control character in any file** (zero-width U+200B-200F/2060-2064/FEFF, tag characters U+E0000-E007F, bidi controls U+202A-202E/2066-2069, other C0/C1 controls; tab, newline and CR are fine; the refusal names the file and the code point), more than 40 files, a file over 200 KB, a skill over 1 MB. `SKILL.md` is required and its `name` must equal the starter id. Nothing is executed.
- **Code that can run is flagged, not only scripts.** A file is marked (in the plan note, the per-file note and the dialog) when it has git mode 100755, a first line starting with `#!`, or an extension that runs (`.cjs .mjs .js .ts .rb .pl .vbs .bat .cmd .ps1 .psm1 .sh .py`). `SKILL.md` frontmatter keys `hooks:` and `allowed-tools:` are shown **verbatim** in the plan notes: Claude Code honours both while the skill is active (hooks run commands, allowed-tools skips permission prompts). A skill with either key, or an unknown license, is **not ticked by default** and is installed only when the user ticks it (`install` in the apply request; omitted means "the ones ticked by default").
- **What the user sees.** The plan returns the FULL text of every file (the whole plan is capped at 1 MB and a larger one is refused, never cut) and the dialog holds all of it: each file is a collapsible block with its byte count; "Показать все файлы полностью" opens every file with no height limit and is required first; then the checkbox "Я прочитал(а) все файлы" becomes available; only then "Установить". A visible note says when a file is longer than the default view. The license is labelled "по данным списка": it is the list's claim, not verified against the repository's license file. The digest covers (id, commit, license, bytes of every file, the code flags); apply fetches again and refuses (409) if it differs, so what is written is exactly what was shown. Reading the text is the user's control; the checkbox is a prompt, not proof of reading.
- **Where it is written, and undo.** Only `HUB_HOME/skills/<id>/` through `planStarter` → `applyStarter` → `applyPlan` (approval, backup, audit). Never `~/.claude`, `~/.codex` or `~/.agents`. A folder that holds a file, or a skill of that name found anywhere on the PC, is skipped ("уже есть"), never merged or overwritten. If `HUB_HOME/skills` is itself a link the install is refused. `.hub-source.json` (id, repo, path, commit, license) is written next to each skill. The backup of a starter install is marked; `POST /api/starter/undo {backupId}` (same token, Host and Origin checks as every write) accepts only such a backup, once, validates the id with the CLI's pattern, restores the earlier files and removes the skill folders when they are empty. The panel shows "Откатить" after an install.

Status: the list rules, the fetcher allow-list, every refusal above (a test per invisible-character class), the pinned-commit/digest property, full-text plans, the flags and ticks, apply, undo (folder gone, second undo and foreign backups refused), the streaming cap and the per-skill budget, and the API are tested with a fake GitHub and a local HTTP server. **Not verified:** a live fetch from GitHub; the license text of the repositories; the four non-fetchable entries (graphify, grill-me, autopilot, senior-architect) because their sources could not be confirmed offline; GitHub's unauthenticated rate limit (60 requests per hour per address; a preview needs one API request per repository plus one per file from raw).

Known limits (accepted): the user's reading is the control (a hostile but plain-text skill that reads innocently to the user is not stopped); the license field is a claim; a pinned sha is only as good as the human who put it there. A skill the user later links to a project is read by an agent: reviewing it is the user's step, the hub only refuses to hide what it installs.
