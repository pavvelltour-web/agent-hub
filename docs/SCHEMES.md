# Agent Hub — схемы

> Статус: **черновик v0.2**, 2026-10-22. Схемы для чтения глазами. Подробности: [ARCHITECTURE.md](ARCHITECTURE.md), [DATA-MODEL.md](DATA-MODEL.md).
> Эти же схемы CLI выводит командой `hub diagram` (раздел 7). В репозитории проекта схемы **генерируются из кода и конфигов**, а не рисуются вручную.

## 1. Архитектура

```
 ВЫ ─► hub CLI ─┐
 ВЫ ─► hub ui  ─┤
                ▼
   ┌─────────────────────────── ЯДРО ────────────────────────────┐
   │  Реестр + lock    Компиляторы       Цикл проекта   Экономика │
   │  (что ставим)     (конфиги агентов) (8 этапов)     (цена)    │
   │                                                              │
   │  Скаут скиллов    Журнал + индекс   Передача       Советчик  │
   │  (поиск нового)   (история)         (карточка)     (модель)  │
   └────────┬───────────────────┬─────────────────────┬──────────┘
            │ адаптеры          │ только чтение       │ запись по OK
   ┌────────┼─────────┐         ▼                     ▼
   ▼        ▼         ▼   ~/.claude  ~/.codex    файлы проекта:
 claude   codex     другие  (история)             hub.yaml  hub.lock
  CLI      CLI     (API/CLI)                      AGENTS.md specs/ .hub/
   │        │         │
   └────────┴────┬────┴──► MCP-серверы (через hub mcp), скиллы, плагины
                 ▼
          git worktree на задачу (ветка hub/<task>/<agent>)
```

## 2. Модель данных

```
 ФАЙЛЫ (источник истины, в git)           БАЗА (индекс, ~/.agent-hub)
 ───────────────────────────────          ─────────────────────────────────────
 hub.yaml      проект, агенты, правила    agent ─< account ─< limit_snapshot
 toolkit.yaml  выбор инструментов            │
 hub.lock      версии + хэши + статусы       └─< session ─< message (FTS)
 specs/…/tasks.md  задачи (Spec Kit)             │      └─< usage_event
 .hub/handoffs/*.md  карточки передачи           │
 .hub/audit.jsonl    подтверждения        project ─< task ─< run ──┘ (run = запуск через hub)
 registry/entries/*.yaml  каталог                       │ ├─ estimate ─ estimate_outcome
                                                        │ └─ handoff (run ─► run)
 registry_entry ─< install (project)      model ─< price
                                          calibration (account × model × effort)
```

```
   │              │               │                │               │               │                  │              │
 context.md    brief.md       toolkit.yaml     architecture.md  AGENTS.md      plan.md             код + status    запись в журнал

                              (скаут+OK)       (senior-         (Spec Kit)     economics.md        ревью           новые уроки
                                                architect)
 ворота: файл-результат есть ─► проверка ─► ваше «OK» ─► следующий этап
```

## 4. Передача работы между агентами

```
 агент A работает ─► лимит: 95% (limit.soon) или отказ (limit.reached)
        │
        ▼
 раннер: стоп + WIP-коммит в ветке задачи
        │
        ▼
 карточка передачи: факты из git и логов (код)  +  смысл (дешёвая модель)
        │
        ▼
 советчик: кто следующий? (остаток лимитов, тип задачи)  ─► ваше OK
        │
        ▼
 агент B стартует в той же ветке с карточкой + спецификацией задачи
```

## 5. Маршрутизация моделей (Claude как основной)

```
 задача ─► класс?
   план / архитектура / ADR / безопасность ─► Opus 5.5  (высокое рассуждение)
   реализация по плану, тесты, правки      ─► Sonnet 5.5 (medium)
   документы, карточки, классификация      ─► Haiku 5.5  (low)

 лестница при затыке (дёшево → дорого):
   Sonnet medium ─ 2 провала ─► Sonnet high ─ провал ─► Opus high + карточка (не весь чат)
   лимит Claude ─► передача Codex (по вашему решению)
 субагенты: по умолчанию выключены; включать, только если счёт показывает выгоду
```

## 6. Схема работы с инструментами

```
 hub scout ─► источники (aitmpl, GitHub, локальные) ─► отбор по проекту
        │
        ▼
 кандидаты: польза │ токены описания │ лицензия │ проверка безопасности
        │
        ▼
 вы выбираете ─► адаптация под агента (diff) ─► hub.lock ─► конфиги агентов
        │
        └─ MCP: hub mcp add ─► проверка ─► запись в конфиг каждого агента (секреты по ссылке)
```

## 7. Как CLI выводит схемы

```
hub diagram arch      [--detail 1|2|3] [--format ascii|mermaid|json]   # архитектура
hub diagram data      [--entity run]                                    # модель данных, можно по сущности
hub diagram stages                                                      # этапы проекта и их статус
hub diagram project                                                     # ЭТОТ проект: агенты, инструменты, задачи
hub diagram handoff   [--id ho-2026-10-22-0007]                         # конкретная передача
hub diagram routing                                                     # правила выбора моделей
hub explain <сущность|этап|компонент>                                   # короткое пояснение + связи
hub diagram … --check                                                   # CI: схемы в docs/ совпадают с кодом
```

- Формат `ascii` по умолчанию, ширина подстраивается под терминал.
- `mermaid` вставляется в README на GitHub.
- `json` — для интерфейса и других инструментов.
- Источники: архитектура из реестра пакетов и адаптеров, данные из схемы базы (`packages/schemas`), этапы из `stages/*.yaml`, проект из `hub.yaml`, `toolkit.yaml`, `hub.lock`.

Пример вывода `hub diagram project`:

```
 amplicore (web-saas)
 ├─ агенты:   claude ✔ (Opus 5.5 / Sonnet 5.5)   codex ✔ (резерв при лимите)
 ├─ этап:     5 Правила ✔ → 6 План ▶ (ждёт ваше OK)
 ├─ скиллы:   senior-architect · ponytail · design-quality-loop · graphify   (4, ≈ 1 100 токенов)
 ├─ MCP:      mobbin ○ не подключён · shadcn ○ не подключён
 ├─ лимиты:   claude ? (нет данных)   codex 50% (сброс через 3 дн.)
 └─ задачи:   12 всего · 3 в работе · 2 ждут ревью
```
