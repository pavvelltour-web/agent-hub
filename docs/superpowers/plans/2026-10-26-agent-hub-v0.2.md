# Agent Hub v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Read "Working principle" and "Skills by step" before the first task.

**Goal:** Make Agent Hub the fastest way into AI-assisted development: modes that really work in both CLIs, a chat and history that look and behave like the real Claude Code / Codex, a **mandatory thorough review stage** for everything agents create, model choice that moves toward "best quality per unit of limit" using evidence, observability (detailed logs, live context gauge, project forecast), and a starter kit (skills, modes, project templates) installed with the panel.

**Phase order:** P0 measure → P1 modes → P2 chat/history → **PR mandatory review** → P3 routing → P4 token economy → P5 starter kit → **P7 observability & forecast** → P6 wrap-up. Once PR is merged, every later phase review runs through the hub's own review pipeline (dogfooding).

**Architecture:** Same single-package, zero-runtime-dependency Node 24 app (ADR-010…015). New work is grouped in six phases; each phase ships working software on its own. Agents are still driven through their CLIs (`claude -p --output-format stream-json`, `codex exec --json`); the hub adds verified mode presets, a richer event model with one renderer shared by live runs and imported history, a (model, effort) router with a verify-and-escalate cascade, and per-task context/tool sets.

**Tech Stack:** Node 24 (type stripping, `node:test`, `node:sqlite`), TypeScript strict (erasable syntax only), plain ES modules panel in `web/`, Claude Code CLI 2.1.114, Codex CLI 0.142.3, graphify (Python 3.14) for the code graph.

**Spec:** this file + `docs/REPORT-v0.1.md` (what exists, what is unverified) + `docs/PLAN.md` (original requirements FR-*/NFR-*) + `AGENTS.md` (repo rules). Reference design (read only the named phase files, never ahead): `nick-vels/skills` → `skills/autopilot/` (MIT).

## Working principle (who does what)

| Role | Model / effort | When | Context |
|---|---|---|---|
| **Executor** | Claude Sonnet 5.5, `high` | every task, by default | fresh per task; gets only the task block, its Interfaces, the files it names, and `graph query` results |
| **Stuck reviewer** | Claude Opus 5.5, `xhigh`, **read-only** (`--permission-mode plan`) | the executor is *stuck* (definition below) | fresh; gets the task, the failing test output (last 40 lines), the diff so far, the handoff card. Returns a cause in one line + a fix plan of ≤ 5 bullets. Writes no code |
| **Fixer** | Claude Opus 5.5, `high` | right after the stuck review | fresh; gets the task, the reviewer's cause + plan verbatim, the failing test. Implements, runs tests |
| **Phase reviewer** | Claude Opus 5.5, `xhigh`, read-only | once at the end of each phase, on the whole phase diff | fresh; returns BLOCKING / FINDINGS (format below) |
| **Cross-check (optional)** | GPT-6.1 Sol via `codex review --base <phase-start>` | phases touching a security boundary (P1, P2, P5) | Codex's own review command; findings are data, merged into the phase review |
| **Review gate** (after Phase PR lands) | the hub's own pipeline: hunters (Opus 5.5 high + GPT-6.1 Sol high), verifiers (Opus 5.5 high), security pass | every later phase and every task branch | replaces the single phase reviewer; its BLOCKING lines go to the fixer verbatim |

**Stuck** = any of: the same test fails after 2 fix attempts; 25 tool calls without a new green test; the executor reports `BLOCKED` / `NEEDS_CONTEXT`; the task needs a design decision the plan does not make.

**Caps (cost rules, from Autopilot's measured runs):** at most 2 repair requests into one executor context, then the stuck path; at most 1 re-review of a fix (scoped to the fix diff); a repair carries the BLOCKING lines **verbatim and nothing else**; reviewers are fresh per event, never long-lived (a 5-minute cache TTL turns a long reviewer context into repeated cache writes). FINDINGS that are not BLOCKING wait for the phase review.

**Review output format** (both reviewers):
```
VERDICT: pass | blocking
BLOCKING: <file:line — condition that must hold> (0..n lines)
FINDINGS: <file:line — issue> (0..n lines, not repaired now)
```
A weakened or deleted assertion is never a fix. The cause comes first, then the fix; no cause found → `BLOCKED`.

**Git:** work on a local branch `v0.2/p<N>-<slug>` per phase; one commit per task; **never push**, never publish (user decision: the GitHub repo is created together after review).

## Global Constraints

- Zero runtime dependencies; a new dependency needs the user's OK and an ADR (ADR-010).
- TypeScript: erasable syntax only (no enums, parameter properties, namespaces); import with `.ts`.
- Spawn processes with argument arrays; never a shell string built from input. Windows first (`C:\`, spaces, Cyrillic).
- Foreign stores (`~/.claude`, `~/.codex`) are read-only; any project write = plan → approval → backup → undo.
- Never read or print secrets; redact tool output **before** it is stored or rendered.
- UI: tokens only from `design/tokens.css`; four themes; body ≥ 14 px, meta ≥ 12 px, targets ≥ 44 px; Russian UI copy, short and plain.
- Test command: `node --disable-warning=ExperimentalWarning --test "src/**/*.test.ts"`; also `npx tsc --noEmit`, `node scripts/security.mjs`, `node bin/hub.js diagram --check`. All green before a task is done.
- Every claim about a CLI behaviour is labelled **observed** (ran it) or **unverified**; unverified behaviour is behind a fallback.

Numbers are vendor- or blog-reported unless noted; treat as priors, replace with own measurements (P0).

| Evidence | Decision |
|---|---|
| Terminal-Bench 4.0 (Vals.ai, 2026-10-24): Opus 5.5 65.2 %, **Sonnet 5.5 64.1 %**, GPT-6.1 Sol 55.1 % | Sonnet 5.5 is the default executor; Opus is for stuck/review, not routine work |
| Artificial Analysis: Sol $2/$10 (cached $0.10), Opus 5.5 $4/$20 (cached $0.20); cost per task at max: Sol $0.72 vs Opus $5.98; SciCode Opus 66.9 vs Sol 54.2 | Sol is the cheap second opinion and bulk/routine option; Opus for hard reasoning |
| DataCamp: Sol stronger per dollar on document Q&A and routine builds; Opus stronger at max effort on automation, terminal/science, computer use (OSWorld 81.8); Sol long-context surcharge above 272K input | vendor-strength priors (P3.2); prompts > 272K prefer Claude |
| Effort studies: high→xhigh adds ~1–4 points at 2–4× cost; in one coding sample Opus 5 low/high/xhigh solved 17/18/16 of 25, cost per solve $0.75→$3.62 | effort is a routed dimension (P3.1); `xhigh` only for short read-only diagnosis/review |
| "Prompt-Induced Waste in Coding Agents" (arXiv 2608.01347): "deep thinking"/"max certainty" wording = 1.3–2.2× reasoning with no success gain; redundant verification up to 18× cost; effort control alone −19 % cost in Claude Code; explicit stopping rules recommended | rules use stop conditions, never "be thorough" (P4.1); effort set per task |
| arXiv 2602.11988: context files do not raise success on average and add > 20 % cost; repository overviews do not help; non-standard conventions do | AGENTS.md keeps only hard rules + non-standard conventions, no repo overview (P4.1) |
| SWE-Pruner (arXiv 2601.16746): reads are 76 % of tokens; targeted retrieval beats large summaries | graph-first reading rule; slices not files (P4.1, P4.4) |
| Autopilot measurements: cost grows ~ with the square of a context; fresh executor optimum ~200–250K; long-lived reviewers waste cache writes; one call per bookkeeping event | fresh context per task, handoff at ~250K (P4.3); reviewers per event |
| Routing/cascade literature (FrugalGPT, RouteLLM, UCCI 2026): cascades with a verifier dominate single-model baselines on the cost–accuracy frontier; cross-family judging reduces self-preference but no proof it finds more bugs | verify-and-escalate cascade (P3.3); cross-vendor review is a quality *bonus*, not a rule |
| Subscriptions (user's case): each vendor has its own weekly limit | the router optimizes "quality per % of limit" and spreads load across vendors |
| "Solving code review at Anthropic" (claude.dev blog): parallel bug hunters + **verifier voting**, style/cleanup filtered out, tags Important / Nit / Pre-existing, every finding answered (fix or reason), separate blocking security pass, effort Quick/Standard/Deep, round cap 3 then "reconsider the approach", diff-only re-review, class-of-bug fixes, no repeated findings; REVIEW.md per area; risk tiers decided by the change; agent approval never replaces a human; approval bound to one commit; incidents/reverts become the reviewer's eval set; one-round pass 65 %→78 %, mean rounds 2.08→1.32; ~59 % of repeat flags were pre-existing code | Phase PR (mandatory review stage) |
| Both CLIs support structured output: `claude --json-schema`, `codex exec --output-schema`, plus `codex review --base/--commit` (observed in `--help`) | reviewers return findings as validated JSON, not prose to parse |

## What we took from Autopilot into our agent rules

Goes into `rules/base.md` (Task 4.1) and the hub's own `AGENTS.md`; each line is a rule, not a retelling:

1. **The user's words are the contract.** A requirement is removed only by the user, in their words; the plan may be corrected, the brief may not. Store the brief verbatim (after redaction) and check the result against it.
2. **One task, one fresh context.** The orchestrator plans and lands; it does not write the project's code. Accumulated context is what breaks long sessions.
3. **Repair has two addresses.** An unfinished job (red check, blocking finding) goes back to the same executor with the condition **verbatim and nothing else**; a failure (BLOCKED, a repair that failed) goes to a fresh context on the stronger model.
4. **Caps:** 2 repairs per context, 1 re-review per fix (scoped to the fix diff), 2 retries and the second only with a changed approach. Running out means the cut was wrong — report it, do not try again.
5. **Cause first, then fix.** A weakened or deleted assertion is not a repair. No cause found → BLOCKED.
6. **Review where it pays:** point review only for the foundation and for sign-in, keys, money, deletion; the whole-branch review always. Three axes reported separately: user's words / spec / craft.
7. **Never invent a fact about the user** (prices, texts, accounts): visible placeholders.
8. **Irreversible or outward-facing actions are a question** in every mode (deploy, publish, pay, message, delete data, rewrite history).
9. **Secrets:** never requested, echoed or written; refer to them by name; a leaked secret is a stop condition.
10. **Read a phase's rules when the phase starts, not before** — anything read early stays in context for the rest of the run.
11. **Wide changes in three green steps:** new next to old → migrate zone by zone → delete the old.
12. **Memory is pointers, not a retelling** — every line of AGENTS.md is paid by every later session.
13. **Acceptance is blind:** a fresh reader checks the result against the brief with the spec withheld, from a clean checkout.
14. **One plain line to the user per finished task** — what became possible, and the count.

## Review Focus

1. **Resume in a mode** — continuing a Codex chat started in "edit" must keep `workspace-write`; today `codex exec resume` gets no sandbox flag. Test in P1.1.
2. **Huge tool output** (a 50 MB log printed by a test) — must be capped and redacted before storage; the panel must stay responsive. Test in P2.1.
3. **Unknown event from a newer CLI version** — renders as a neutral "unknown event" row, never crashes the stream or the history view. Test in P2.1.
4. **Cascade on a flaky or impossible test** — stops at the caps, writes a handoff card, never edits the test's assertions. Test in P3.3.
5. **Cyrillic / spaces in paths and prompts** through modes, resume and history — args stay intact. Test in P1.1 and P2.3.
6. **Review that never converges** (author agent and reviewer agent ping-pong) — stops at 3 rounds with "reconsider the approach", never repeats a posted finding. Test in PR.5.
7. **A reviewer that "approves" by prose** or returns malformed JSON — treated as no review, the gate stays closed. Test in PR.2.

## Phase PR — Mandatory thorough review (a gate, not an option)

**Rule:** no task branch is accepted ("Принять результат" / merge into the project) while the review gate is open. The gate covers **everything the agent created**: code, tests, configs, migrations, docs, `AGENTS.md`/rules, dependency changes, generated files and UI (rendered screenshots). Load `senior-architect` for PR.1, `security-review` for PR.4, `product-ui-workbench` + `design-quality-loop` for PR.7.

Pipeline per review round (shown in the panel as a stepper):

```
0 Checks      tests · typecheck · lint · build · secrets scan · dependency audit   (red = gate closed, no AI review spent)
1 Hunt        N parallel bug hunters, each with one lens, read-only, structured JSON
2 Verify      each finding checked by K independent verifiers; kept only on majority "real"
3 Filter      drop style / cleanup / diagnostics; tag Important · Nit (≤ 5 shown) · Pre-existing
4 Security    separate pass; any open security finding blocks
5 Risk        tier from the change (low / medium / high); high needs a human approval bound to the commit
6 Answer      every Important/Security finding: fixed (auto-cleared by a later commit) or closed with a reason
7 Converge    round cap 3 → "reconsider the approach"; re-review only the new diff; no repeats
```

Effort (per project, default Standard):

| Effort | Hunters (lenses) | Verifiers per finding | When |
|---|---|---|---|
| Quick | 1 (correctness) | 1 | mechanical tasks, docs |
| Standard | 3 (correctness/root cause · edge cases & data · intent vs brief) | 2 | default |
| Deep | 5 (+ concurrency/process · UI & copy) | 3 | foundation, sign-in, keys, money, deletion, installers, CI files, migrations |

Models: hunters alternate vendors (Claude Opus 5.5 high, GPT-6.1 Sol high) — diversity of failure modes; verifiers are Opus 5.5 high; the lens "intent vs brief" always runs blind to the spec (brief + diff only). On subscriptions, the gate shows the expected % of limit before it starts.
