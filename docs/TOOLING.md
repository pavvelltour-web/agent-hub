## 1. Главная проблема: слишком много включено

В Claude Code включено 42 плагина, в Codex 67. В списке скиллов одной сессии Claude сотни строк, и описание каждого платится токенами **на каждом ходу**. Заметные дубли и лишнее:

- Одни и те же Airflow-скиллы стоят три раза: плагины `data`, `data-engineering` и `astronomer-data`.
- Плагины облаков и сервисов, не связанные с проектом (AWS, Firebase, Cloudinary, Netlify, Asana, Atlan, Atlassian, Discord, Pinecone, Figma, Bright Data, Fastly).
- В `~/.claude/skills` лежат всего три скилла (`brand-guidelines`, `discovery-interview`, `graphify`), а дизайн-, архитектурные и ревью-скиллы лежат в `~/.agents/skills` и `~/.codex/skills` и до Claude не доходят.

Это задача части 1: профиль под проект и общая библиотека. Для разработки панели включаем **только набор из разделов 2–6**.

## 2. Обязательные скиллы по вашему решению

### 2.1. Архитектура: `senior-architect`

- Лежит в `~/.agents/skills/senior-architect` (и в AmpliCore). Это набор из трёх скриптов (`architecture_diagram_generator.py`, `dependency_analyzer.py`, `project_architect.py`) и трёх справочников (паттерны архитектуры, процесс проектирования систем, руководство по выбору технологий).
- Используем: этап 4 жизненного цикла и дизайн каждой части. Генератор диаграмм этого скилла — основа для `hub diagram arch`, а вывод проверяется на соответствие нашему коду.
- Подключаем к Claude через junction (сейчас он до Claude не доходит).

### 2.2. Малый код: `ponytail` (вы называли «понятейл»)

- Репозиторий DietrichGebert/ponytail, лицензия MIT. У вас уже стоит в `AmpliCore/.agents/skills/ponytail` и есть как маркетплейс в кэше Codex.
- Идея: «ленивый старший разработчик». Сначала вопрос, нужна ли задача вообще, затем стандартная библиотека, затем платформа, затем зависимость, затем свой код. Режимы `lite`, `full` (по умолчанию), `ultra`.
- Заявленный эффект по данным автора (по сторонним описаниям): на 12 задачах с Haiku 4.5 код короче в среднем на 54%, токенов меньше примерно на 22%, цена ниже примерно на 20%. Выборка маленькая, источник — сам автор. **Мы это не проверяли**, поэтому эффект измеряем на ваших задачах (раздел 4).
- Применяем: `full` для реализации; `lite` для кода безопасности, путей, процессов и обработки ошибок (где «минимальное» не должно срезать проверки); не применяем для документов и архитектуры.

### 2.3. Дизайн: ваш пайплайн `product-ui-workbench` + `design-quality-loop`

Оба скилла ваши (подтверждено вами 2026-10-22) и **обязательны** на этапе дизайна для любого проекта с интерфейсом; рекомендатор не может их заменить.

- **`product-ui-workbench` 0.10.1** — `Desktop/design-pipeline-2026-10-18-v15/plugin`. Портативный плагин (MIT) с манифестом Claude, скиллом и Python-скриптами: `design_loop.py` (зафиксированный промпт и бюджет итераций), `browser_probe.py` (реальные проверки в Chrome), `theme_matrix.py` (парные светлая/тёмная темы), `pattern_catalog.py`, `ux_discovery.py`, `render_web.py`, упаковка. Цепочка: сценарии → UX-решение → реальные экраны → разбор → паттерны → промпт до кода → калибровка → рендер → сравнение → проверки состояний → независимая критика → экспорт. Нужен Python 3.10+, для рендера — Playwright и Chrome (сам ничего не устанавливает).
- **`design-quality-loop` 2.0** — `~/.codex/skills/design-quality-loop`: арт-дирекшн от референсов Mobbin и реализация на shadcn/ui с честными статусами.
- Сейчас оба доступны только Codex (плагин не установлен ни у одного агента). Часть 1 подключает их обоим.
- MCP для них: Mobbin и shadcn, инструкция в [MCP-SETUP.md](MCP-SETUP.md).
- Дизайн-система панели собрана по их правилам (парные темы, роли типографики, контраст в реальных потребителях): [../design/DESIGN-SYSTEM.md](../design/DESIGN-SYSTEM.md).
- Для типа «мобильное приложение» в пакет знаний добавляются также `mobile-design` (в `~/.agents/skills`, 394 строки) и `imagegen-frontend-mobile` (у Codex); чья это разработка, не знаю.

## 4. Экономия токенов без потери качества

| Мера | Что даёт | Как проверяем |
|---|---|---|
| `graphify`, один граф на проект | агент читает отчёт графа, а не перебирает репозиторий; сейчас `graphify-out` копируется в каждый worktree | замер «до и после» на одном наборе задач |
| `ponytail` | меньше кода и меньше вывода | то же; заявленные 22% токенов проверяем сами |
| Профиль скиллов под проект | меньше токенов описаний на каждом ходу | считаем `token_cost` профиля |
| Короткий стабильный `AGENTS.md` | кэш не ломается (97,9% входа у вас кэш) | доля кэша в логах |
| Без субагентов по умолчанию | у вас 57% токенов Codex ушло в субагентные треды | сравнение расхода |
| Лестница моделей (дёшево → дорого) | дорогая модель только при затыке | MODELS-AND-LIMITS, раздел 6 |
| Sparse-checkout в worktree | агент не ищет по лишним файлам | размер контекста |

Правило приёмки каждой меры: токенов стало меньше **и** доля задач, прошедших с первой попытки, не упала. Набор для замера — 10 задач из вашей истории; сравниваем 4 варианта: без мер, только `graphify`, только `ponytail`, оба.

Кандидаты для скаута (в сравнительной статье названы как инструменты экономии токенов; мы их не изучали): `caveman` (сокращает слова в ответах), `rtk`, `headroom`, `pxpipe`. Устанавливать только после проверки безопасности и замера.

### harness2 (Google Research)

Прочитал страницу репозитория. Выводы:

- **Это не скилл**, а отдельный фреймворк с CLI, который автоматически улучшает «обвязку» агента (промпты, инструменты, память, скиллы) под задачу. Лицензия Apache-2.0, не официальный продукт Google.
- Требования: Linux, Python 3.12, `uv`. Для работы с моделями Node 20+, Google Cloud CLI и настройка Vertex AI; для части бенчмарков Docker.
- Исполнитель по умолчанию — OpenCode, Codex поддержан через отдельный режим. **Claude Code на странице не упоминается.**
- Про экономию токенов страница ничего не заявляет, а заявленные улучшения качества получены на бенчмарках авторов и мною не проверены.
- Безопасность: по тексту страницы, сеть исполнителя не ограничена, а Codex запускается с отключённой песочницей. Это совпадает с угрозой T10 в SECURITY.
- Зрелость: у репозитория много звёзд (около 17,7 тыс.), но на странице видно всего 3 коммита и нет релизов; свежесть определить не удалось.

**Решение:** в версию 1 не включаем. Берём идею — по итогам этапа 8 агент предлагает правки к правилам и скиллам с доказательствами — и реализуем её просто, через карточки «уроков» с вашим подтверждением. Если захотите запускать сам harness2, то только в Docker или WSL с закрытой сетью и отдельной задачей в плане.
